# i18n for permissionless.money

**Goal:** Curate dedicated language packs (not machine-only strings) while keeping the static HTML + `build.js` pipeline.

## Recommended model: JSON catalogs + dual delivery

| Piece | Role |
|-------|------|
| `locales/<lang>/<page>.json` | **Source of truth** for copy (curated translations) |
| `pages/*.html` | English structure; mark strings with `data-i18n="key"` |
| `lib/i18n.js` | Client: detect locale, load JSON, apply to DOM, switcher |
| `build.js` (optional next step) | Emit `/es/zk.html` etc. with strings pre-filled for SEO |

### Why not “full React/i18next rewrite”?

This site is a few large HTML desks. Catalogs keep **curators** (not engineers) editing JSON; HTML stays the layout shell.

### Why not “duplicate whole HTML per language” first?

Works for 1–2 pages, then **drifts**. Use JSON keys from day one; only fall back to full HTML forks if a locale needs radically different layout.

## HTML markup pattern

```html
<html lang="en">
…
<h1 data-i18n="hero.title">More places Zcash guarantees can settle.</h1>
<p data-i18n="hero.essence" data-i18n-html>…optional HTML…</p>
<a data-i18n="cta.forum" href="…">Forum</a>
<meta name="description" data-i18n-content="meta.description" content="…">
```

| Attribute | Use |
|-----------|-----|
| `data-i18n="key"` | Set `textContent` |
| `data-i18n-html="key"` | Set `innerHTML` (trusted translations only) |
| `data-i18n-attr="placeholder:form.email"` | Set attribute |
| `data-i18n-content="meta.description"` | For `<meta content>` |

**Default English stays in the HTML** so the site works without JS and as the catalog seed.

## Client runtime (`lib/i18n.js`)

1. Resolve locale: `?lang=es` → `localStorage.pm_lang` → `navigator.languages` → `en`
2. Only **AVAILABLE** packs apply (`en`, `es` today). Switcher lists `SUPPORTED` but disables langs without packs.
3. `fetch(/locales/${lang}/common.json)` + page pack (`zk.json` if path includes `/zk`)
4. Deep-merge over `en` fallbacks (missing keys never blank the UI)
5. Walk `[data-i18n], [data-i18n-html], [data-i18n-attr], [data-i18n-content]`
6. Set `<html lang="…">`, update `document.title`
7. Language switcher re-applies **without full reload** and emits `pm:i18n` (`detail: { lang, msgs }`)

### Anti-flicker (FOUC)

Non-English paints would flash English while packs load. Pages include an **early head script** that:

1. Reads `?lang=` / `localStorage.pm_lang`
2. If the lang is in `AVAILABLE` and not `en`, adds `html.i18n-pending`
3. CSS: `html.i18n-pending body { visibility: hidden }`
4. `initI18n` / `applyLang` remove pending and set `html.i18n-ready` after apply (2.5s safety timeout)

English first paint stays visible (no hide).

### URL strategy (pick one)

| Strategy | URLs | SEO | Notes |
|----------|------|-----|--------|
| **A. Query / storage (start here)** | `/zk?lang=es` | Weak | Fastest to ship |
| **B. Path prefix (better)** | `/es/zk`, `/zh/zk` | Strong | Needs nginx + build emit |
| **C. Subdomain** | `es.permissionless.money` | Strong | Ops-heavy |

**Recommendation:** Start with **A** for the grant desk; move to **B** when you have ≥3 curated languages.

### Nginx sketch (path prefix later)

```nginx
# Prefer /es/* static files when present; else fall back to en shell + client i18n
location ~ ^/(en|es|zh|ja)/(.*)$ {
  try_files /$1/$2 /$1/$2.html /$2 /$2.html =404;
}
```

## Build pipeline (phase 2)

Extend `build.js`:

1. Read `locales/en/*.json` as baseline.
2. For each lang in `LOCALES = ['en','es','zh']`:
   - Load pack, merge.
   - For each page, clone HTML, apply substitutions server-side (same rules as `i18n.js`).
   - Write `dist/es/pages/zk.html` or `dist/es/zk.html`.
3. Always also ship `dist/locales/**` for runtime switcher.

That gives **static SEO pages** + **client switcher** for incomplete locales.

---

## Curation workflow (human translations)

1. Freeze English keys when a panel is “done.”
2. Export key list: `node scripts/i18n-extract.js` (scan `data-i18n` attrs).
3. Translators edit only `locales/<lang>/*.json` (PR review).
4. Optional: CI check that every `en` key exists in `es` (warn, don’t fail on partial).
5. **Do not** auto-machine-translate into production without a curator pass — especially grant claims.

## What to mark first (zk desk priority)

| Surface | Priority |
|---------|----------|
| `meta.*`, hero, side grant card | P0 |
| Essence / problem / stack cards | P0 |
| Timeline + community event | P1 |
| Auth, demos, progress | P1 |
| Contact (keep emails/URLs untranslated) | P2 |
| Code identifiers, repo names, ZIP numbers | **Never translate** |

Keep links/paths language-stable; only visible labels change.

## Anti-patterns

- Translating legal/grant dollar amounts inconsistently  
- Different milestone numbers per language  
- Runtime-only i18n for the only public grant page (SEO suffers) without eventually prebuilding  
- One giant `all.json` (merge conflicts); split by page
