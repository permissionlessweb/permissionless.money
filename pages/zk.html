Problem → path

A selective-disclosure VM and smart-contract path for extending the edge of the Zcash ecosystem with native interop — so DAOs can verify, bridge, and compose with native Zcash material.

Where this sits

Privacy and consensus live in core Zcash. This residual extends the ecosystem at the edge: a contract VM and light-client surface that speak Zcash-grade proofs, curves, and headers so existing and new DAOs can act on them through native interop.

What the path delivers

In-contract proof verification, header and finality updates into light clients, claim binding on smart accounts, and DAO gates for membership, voting, and access — privacy composability with native Zcash across the bridge path.

The path · Verify → Update → Bind → Gate

Four steps from proof verify to DAO action along that edge interop path:

  1. 01Verify — settle Zcash-grade proofs in the selective-disclosure contract VM. Param files, circuit footer, tiered cache on the proof VM.
  2. 02Update — carry Zcash headers and finality into light clients contracts can read. Header / Crosslink finality ingress on the IBC light client path.
  3. 03Bind — attach verified claims to smart accounts and authenticators. Curve-aware authenticators (terp-rs suite).
  4. 04Gate — DAO membership, voting, and access from those claims. DAO plugin actions and wallet-derived session material.
For reviewers · design alignment

Each step reuses Zcash-aligned crypto (selective disclosure, coinholder-voting style commitments, Crosslink finality) on the contract and light-client edge so DAOs gain native interop and composition without reimplementing the core chain.

Builds alongside existing ZIPs and community tooling for those same surfaces.

Auth & access

Authenticators and DAO plugins that bind verified Zcash-native claims to membership, voting, and access along the interop edge.

Capabilities

  • Smart authenticators (terp-rs priority) — multi-credential gates (passkeys, curve credentials, membership) on accounts/DAOs; compose with IBC light clients for ZK authentication gateways. Library substrate: smart-account-auth.
  • vote-sdk DAO plugin — eligibility + ballot commitments that verify under the proof VM without roster dumps. vote-sdk
  • Wallet-derived sessions — sessions extended with Zcash-native curves so auth can derive from existing wallet material.

Prove entry, not identity graphs

Gates check a claim (set membership, note hold, role) with minimal disclosure — the same discipline selective disclosure and coinholder voting already assume. Reveal only what the policy requires.
